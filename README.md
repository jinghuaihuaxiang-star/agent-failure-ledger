# rea

把 agent 的失败日志变成两个可核的数：**真失败率**，和**被机制化（有证据压住）的失败类数**。

> Two numbers you can actually audit: the *real* failure rate of an agent, and the number of failure classes a mechanism has provably suppressed.

---

## 这个仓库解决三个骗过我的读数

**1. 「错误数下降」不一定是进步。**
退出码、报错、`grep` 无匹配、管道早停、检查器按设计判 FAIL、探针验它会不会拒绝——全都返回非零。混在一起数，读数就随「今天查了多少次」而不是「今天错了几次」波动。
实测：原始 60.6 / 千步 vs 真失败 38.3 / 千步，**差 37%**。只报一个数的时候，噪音会被当成进步。

**2. 「规则越写越多」不一定是进步。**
规则是文本，文本不会执行自己。一条写坏的规则不会报错——它只是永远不命中，而读数照样「正常」。
本仓库的做法：规则必须配**合成样本自检**，退化当场就被抓住；规则只是归因，**从不降桶**，说不清就是真失败。

**3. 「建了多少工具」不是复利。**
建了工具 ≠ 压住了失败。一项机制要算「生效」，必须同时满足四条：

| 条件 | 排除的自欺 |
|---|---|
| ① 产物在盘上 | 「我记得写过」 |
| ② 探针真跑过 | 文件存在不等于它会拦 |
| ③ 落地前 7 天该类真失败 ≥2 次 | 没有前科就没有「压住」可言 |
| ④ 落地后 7 天里一次都没有 | 后窗口没满只能算「观察中」 |

`declared`（有机制、但没有可测前科或没有探针）单列，**永不进主指标**。

## 组件

| 文件 | 干什么 | 规模 |
|---|---|---|
| `src/classify.mjs` | 把失败调用分成 6 个桶（真失败 / 检查器拒绝 / 探针 / 工具链惯用法 / 被终止 / 环境）；真失败再按 25 条根因归因；自带 17 例合成样本自检 | ~410 行 |
| `src/ledger.mjs` | 双口径读数（原始 vs 真失败 / 每千次调用）+ 根因聚类 + 单根因的形态分布 | ~110 行 |
| `src/mech.mjs` | 机制量表：上面那四条判据；纯函数 `judge()` + 8 例自检 | ~190 行 |
| `src/edit-safe.mjs` | 改文件单入口：先读 → 写前重读核对 → 写 → 回读 → 语法检查 → 坏则回滚。让「没先读 / 版本失配 / 锚点不唯一」结构上不可能发生 | ~180 行 |

零依赖，纯 Node（≥18，用到 `node:fs` / `node:child_process`）。

## 快速开始

```bash
node src/classify.mjs --selftest
node src/classify.mjs --in samples/events.sample.jsonl --window 30
node src/ledger.mjs   --in samples/events.sample.jsonl --calls 400 --top 6
node src/mech.mjs     --events samples/events.sample.jsonl --registry samples/mechanisms.sample.jsonl
node src/mech.mjs     --selftest
```

样例输出：

```
窗口 全部 / 失败调用 20 条
  真失败                                     12   60.0%
  检查器 / 守卫按设计拒绝（缺陷另记账）       1    5.0%
  探针 / dry-run（预期非零）                  1    5.0%
  工具链惯用法（命令干成了，退出码骗人）      3   15.0%
  进程被终止                                  1    5.0%
  环境 / 配置（换写法也过不去）               2   10.0%
```

```
每千次调用：原始错误 50.0 / 真失败 30.0  （差值 20.0 = 噪音）
两个数必须一起报。只给一个的时候，噪音会被当成进步。
```

        落地前 3 次 → 落地后 7 天 0 次

## 数据从哪来

**输入是一份 JSONL，一行一个失败调用。** 字段和最小可用做法见 [docs/02-输入格式.md](docs/02-输入格式.md)。

你需要的只有两样：每次工具调用之后的 `tool / cmd / exit / out / err`，以及一个总数（用来算每千次）。多数 harness 的 trace、日志、`~/.<agent>/sessions/` 都能导出来——写一个 20 行的转换脚本就够了。

`--calls` 是同一窗口里的**调用总数**（不是失败数）。分母必须稳定，否则「今天查得多」会伪装成「今天错得多」。

---

## 三条设计原则

1. **fail-closed**：没命中任何规则的一律算真失败。宁可高估，不给自己免检。
2. **归因不降桶**：根因分类只回答「下一刀砍哪里」，绝不因为「我能解释它」就把它移出真失败。
3. **闸坏了不能静默放行**：分类器输出不干净（有非 JSON 行、分母对不上）时，整个量表报错退出——偏小的分母会把「漏了的失败」看成「压住了」。

---

## 局限（不假装修好）

- **规则表是某一台机器的形状**：Windows + PowerShell 5.1 + 一个自研 harness。换环境要按自己的失败形态重写。表本身不是重点，「桶不混、归因不降桶」这个结构才是。
- **它需要时间序列**。没有前 7 天 / 后 7 天的事件，`mech.mjs` 是空转的。这是它最脆弱的地方——它不是在测代码，是在测「一段时间里发生了什么」。
- **分类器覆盖不到的失败永远是 `declared`**。比如「我理解错了需求」这种，日志里没有可测签名。这类刻意不假装能测。
- **`edit-safe` 不是并发协调工具**：写前核对 sha 与真正落盘之间仍有微秒级窗口，文件系统没有原子 compare-and-swap。
